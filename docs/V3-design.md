# personal-ai-dashboard V3 设计定稿：三线四层编译器工作台

> 状态：**v1.0 设计定稿（方案阶段）。未经用户批准不进入实施。**
> 本文档综合了用户访谈 + 13 部抖音知识库/工作台视频的转写分析 + Karpathy LLM Wiki 公开资料调研。
> 确认后：第 3 章固化为仓库 `CONTEXT.md`，第 7 章生成实施路线图文件，旧 `personal-ai-dashboard-roadmap.html` 归档保留。

## 1. 背景与诊断

### 1.1 现状

现有系统是一套**为自媒体内容创作者打造的、治理极其严谨的采集型知识库**（采集闭环 + 知识工作闭环 + 可靠性治理均已实现，且严谨度在个人项目中罕见）。

### 1.2 为什么不满意（六个错位）

| # | 错位 | 说明 |
|---|------|------|
| 1 | **采集驱动 ≠ 目标驱动** | 整个 P1 围绕"投递一份视频"设计；而生活重心是"考公上岸 + 出片"两个目标。系统在帮你收藏内容，没有帮你推进目标。 |
| 2 | **重治理 ≠ 单人日常** | 五层记忆晋升机制、多智能体角色矩阵、P2 快照准入状态机、design-lab 双轨、双 Graph——是"自进化智能体"野心的遗产。 |
| 3 | **情报能力缺失** | "每天/每周自动搜集关心内容"只有单源 AI 热榜原型；考公时政/公告、短剧市场、MES 动态全部没有。 |
| 4 | **领域工作台缺失** | 考公、AI 视频、小说在旧路线图 P3 只是"领域模板"设想；MES 经验沉淀完全不在视野里。 |
| 5 | **Agent 记忆与迁移难受** | 跨会话/跨工具丢背景，项目迁移要反复交代。 |
| 6 | **不够智能** | AI 只做了"整理柜"里的点缀：摘要、分类、建议。真正需要的智能是**AI 主动判断、生成、行动，人只做投递和确认**。 |

### 1.3 设计目标（已与用户确认）

1. **双主线并跑**：考公线与创作线同等地位，MES 为轻量沉淀线。
2. **创作线聚焦 AI 短剧/漫剧**；长篇 AI 润色留作二期。
3. **全自动情报采集 + AI 初筛**：人只做"入库/丢弃"。
4. **Agent 有记忆、项目可迁移**：新会话/新工具读六槽记忆即可无痛接续。
5. **智能优先**：AI 主动判断/生成/行动；降体积、降维护（≤15 分钟/天）。
6. **前台重设计**：安静书桌，不是指挥中心。
7. **吸收现有代码优点**：不丢弃已验证的治理资产。

## 2. 核心范式：编译器模式（Compiler Mode）

源自 Karpathy 的 LLM Wiki，被全部 13 部视频独立验证：

> **AI 不是"你问它才读"的解释器（RAG），而是"提前把资料编译成结构化知识、随用随取"的编译器。积累而非消耗，从临时拼凑变成提前整编。**

- **投递 → 编译 → 沉淀 → 复用**：任何输入（链接/笔记/对话/问答）经 AI 编译成结构化卡片/Wiki 页，自动建链；查询基于完整体系作答，优质问答再回填成新页。
- **三层分离**：①原始素材永不动（事实源头 truth source）→ ②Wiki 知识库（AI 编译产物 = 系统大脑）→ ③统一规则文档（库规，保证一致性）。
- **人机分工**：**方向由人判断，维护由 AI 承接**。AI 产物一律先进"待确认"，人工确认降载为"只审 AI 标记的不确定处"。
- **反对 RAG 重工程**：无向量库、无 chunk 调优起步；纯本地文件夹 + Markdown + LLM。轻检索只作补充，需要时再评估。

## 3. 域模型（统一语言）

### 3.1 三条线

| 线 | 目标 | 资产产出 | 情报关注 |
|----|------|----------|----------|
| **考公线**（主线 A） | 上岸（约半年后考试） | 知识点卡、错题、时政素材、报考情报、周计划、模考记录 | 时政、政策变化、招考公告、分数线、备考方法 |
| **创作线**（主线 B） | 出片（AI 短剧/漫剧，未启动） | 剧项目、剧本、分镜、镜头提示词、角色卡、设定集、成片复盘 | AI 视频工具动态、短剧/漫剧市场、平台规则、风格案例 |
| **职业线**（沉淀线） | 经验不丢（MES） | 故障卡、技术决策、代码片段、项目复盘 | MES/制造业软件动态、行业案例 |

### 3.2 四层

| 层 | 职责 | 载体 |
|----|------|------|
| **记忆层** | 我是谁、偏好风格、项目状态、决策与交接、犯错档案（给 Agent 读） | Vault `00-个人档案` + 各项目 `CONTEXT.md`/`docs/adr/`/`docs/handoff/` + `08-智能体运行`（共创录/迭代日志/犯错档案） |
| **情报层** | 自动采集、AI 初筛、每日简报、入库/丢弃判断 | System 运行区（可重建）+ 简报 |
| **知识层** | 原始素材（不动）+ 编译产物（Wiki/卡片）+ 库规 | Vault `04-来源资料`（truth）/`06-正式知识`（编译产物）/规则文档 |
| **工作层** | 三线任务、资产、产出、复盘 | Vault 线内资产目录 + Workbench 状态 + AI 自治任务看板 |

### 3.3 核心对象

统一字段（知识/资产对象）：`line`、`layer`、`user_confirmed`、`source_refs`、`review_after`（TTL）、`ai_provider/ai_model/prompt_version/generated_at`。
记忆对象额外字段：`written_by`、`confirmed_by`、`ttl`、`superseded_by`。

**记忆六出口（分槽记忆）**：一次重要对话结束后按类型拆写六槽——
①对话全文→**共创录** ②当日状态→**日记复盘** ③偏好/表达/判断方式→**用户画像** ④设计原因→**决策记录(ADR)** ⑤规则变化→**迭代日志** ⑥AI 错误→**犯错档案**。新会话/新工具读完六槽 = 无痛接续。

| 对象 | 定义 | 关键边界 |
|------|------|----------|
| **Profile 个人档案 / Preferences 偏好** | 我是谁、三线目标、协作偏好 | 仅用户确认可写；不进公开仓库 |
| **ProjectContext 项目上下文** | 当前状态、关键决策、下一步、边界 | 状态段 Agent 可高频更新（TTL+审计）；已确认段仅用户可改 |
| **HandoffNote 交接笔记** | 会话/任务结束的交接：做了/卡了/下一步/风险 | Agent 可写、只追加、下次必读 |
| **IntelItem 情报条目** | 候选信息：标题、来源、命中主题、AI 初筛摘要、建议动作、**"与你何干"** | 不是 Raw；未入库前只在运行区 |
| **Raw 原始素材** | 已入库来源，**入库后永不动**（truth source） | 单段（一次确认）或双段（附已审核摘要） |
| **Wiki 知识** | AI 编译产物：结构化页/卡片 + 双向链接 | 编译即沉淀；查询回填也生成 Wiki 页 |
| **KnowledgeCard 知识点卡** | 考公线：可独立复习的知识单元 | 由 Raw/教材编译，不是 Raw 本身 |
| **MistakeRecord 错题** | 题目、错因归因、科目、下次复习日 | 独立录入；AI 归因必须引用依据 |
| **PolicyDigest 时政素材 / RecruitmentInfo 报考情报** | 申论可用要点 / 公告职位时间 | 强 TTL；过期提醒不删除 |
| **StudyPlan 周计划** | AI 建议、用户确认的复习安排 | User Override First |
| **DramaProject / Script / Storyboard / ShotPrompt** | 剧项目容器 / 剧本 / 分镜 / 镜头提示词 | 资产，不是知识 |
| **CharacterCard / SettingSheet** | 角色卡 / 设定集 | 一致性检查数据源 |
| **ShotPostmortem 成片复盘** | 镜头可用率、返工原因 | 沉淀为可复用提示词库 |
| **IncidentCard / TechDecision / Snippet** | 职业线 30 秒轻记录三件套 | 月末 AI 归纳为案例 |

### 3.4 状态机（编译模式）

```
IntelItem:  new ──AI初筛(个性化取读)──▶ triaged ──用户判断──▶ saved(生成Raw草稿) / dropped
Raw 单段:   draft ──用户确认──▶ published（此后永不动）
Raw 双段:   draft ─▶ summary_draft ─▶ reviewed ──确认──▶ published
                                    └──(高价值)──▶ 编译为 Wiki/卡片 ──确认──▶ published(Wiki)
编译回流:   查询/对话/问答 ──AI编译草案──▶ 用户确认（只审不确定处）──▶ Wiki/六槽记忆
记忆写入:   Agent ──候选/交接──▶ 用户确认 ──▶ 正式记忆；项目状态段例外（TTL+审计）
```

User Override First 全链路保留：AI 只建议；用户修改/确认后任何重算、刷新、跨日流程不得覆盖。

## 4. 智能增量十条（本设计的核心，收敛自全部视频）

**A. 内核：编译**
1. **编译即沉淀**：任何输入/对话/问答结束 → AI 编译成结构化卡片/Wiki 页 + 自动建链。人工确认降载为"只审 AI 标记的不确定处"。
2. **随手丢**：链接/一句话/灵感/故障记录统一投递入口；AI 按**文件归属决策树**自动分拣预归档（有终点→项目；长期→领域；一次性→资源；观点→卡片盒；时间线→日记），人只抽查。
3. **只做增量 + 单向流**：AI 消化只碰新卡片、不重跑旧的；灵感→卡片→长期区**单向不可倒灌**；临时区 TTL 可配（不设 30 天硬删除）。

**B. 主动智能：每日循环**
4. **每日主动产出**：早上自动生成「昨日三线进展 + 今日建议 + 个性化必读情报 + 选题推荐」；晚上生成复盘草稿。
5. **库体检（lint 式）**：定期扫矛盾/缺关联/未提炼/领域空白 → 出处方 → 转待办（AI 自治看板）→ 逾期提醒。**对考公线 = 薄弱点识别器**。
6. **判断有据**：AI 做任何判断/建议前走**启动检查五步**（任务判断→系统索引→记忆检索→涉判断则读画像→按模式执行）；只读相关库（个性化取读）；**引用你的笔记/逻辑卡片并展示依据**——不准乱判。

**C. 记忆：Agent 有记忆**
7. **记忆六出口分槽**（见 3.3）：新会话/新工具读六槽即无痛接续，解决"迁移项目难受"。
8. **错误免疫**：关键任务执行铁律（不许凭感觉）；犯错分级记档（**同一错误 ≥2 次才入库**）；自信度路由（不确定先验证，验证不了就明说）。

**D. 复利：产出回流**
9. **从库长出**：写稿/写剧本/做选题前强制先取"画像 + 过往产出 + 卡片盒 + 情报"再动笔——临时写稿是消耗，从库长出才是复利；重复 ≥3 次的方法沉淀为 skill；外部好 SOP 提炼入库。
10. **复利指标**：看板显示导入数/问答回填数/矛盾修正数/skill 复用率——**不显示笔记数量虚荣指标**。

## 5. 系统架构

### 5.1 总览

```
┌ 记忆层（六出口分槽）─────────────────────────────────────────┐
│ 画像/偏好 | 项目CONTEXT/ADR/交接 | 共创录/迭代日志/犯错档案      │
└──────────────┬──────────────────────────────────────────────┘
        task-start 启动检查五步 / task-close 写交接+六槽拆写
┌ 情报层 ─────────────────────────────────────────────────────┐
│ 订阅(主题+源+频率) ─▶ 采集器(RSS/热榜/公告/时政) ─▶ AI初筛(个性化取读) │
│ ─▶ 每日简报 + 选题推荐 ─▶ 随手丢一键入库                        │
└──────────────┬──────────────────────────────────────────────┘
┌ 知识层（编译器） ─────────────────────────────────────────────┐
│ 收集箱 ─▶ 整理箱(编译/建链/只做增量) ─▶ 沉淀箱                  │
│ 原始素材永不动(04) | Wiki/卡片(06) | 统一规则文档 | lint式体检    │
└──────────────┬──────────────────────────────────────────────┘
┌ 工作层 ─────────────────────────────────────────────────────┐
│ 考公台 | 创作台 | MES台 | 三线今日 | AI自治任务看板 | 周/月复盘    │
│ 从库长出(产出) ─▶ 复盘 ─▶ 回填知识层/记忆层（复利）              │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 从 V2 继承（代码优点清单）

| 资产 | 继承方式 |
|------|----------|
| Vault 布局与 Markdown-first 契约 | 不变；`04-来源资料`=truth、`06-正式知识`=编译产物、`08-智能体运行` |
| User Override First | 全链路保留 |
| 双人工门 | 只用于双段链路；单段一次确认 |
| 写前快照、原子替换、Git 审计 | 发布事务不变 |
| 隐私分级 + 外发确认 | 情报采集与 AI 初筛同样遵守 |
| AI Provider 抽象 + provenance | 初筛/编译/归因/创作辅助共用同一抽象 |
| System Health / Diagnostics / Maintenance | 保留页面，冻结功能扩展 |
| attention 配置 + 三档阅读分层 | 升级为情报引擎初筛核心 |
| 采集适配器（抖音/网页/转写） | 保留为入库通道之一，不再是重心 |
| 旧决策"Markdown HandoffPacket 第一阶段" | 保留：记忆层文件先行 |

### 5.3 新增组件

**A. Memory Layer 记忆层**：六出口分槽 + 启动检查五步 + 用户画像路由 + 犯错档案（≥2 次才入库）+ 交接笔记模板。`MemoryProvider` 接口预留（AgentMemory/Handoff 产品为可选后端），当前纯文件实现，未来切换不需迁移格式。

**B. Intel Engine 情报引擎**：订阅模型（主题+源+频率+隐私级+目标线，内置考公/创作/职业三组）→ 采集器合同 `fetch→normalize→dedupe→hash`（RSS/热榜/公开公告页/时政源）→ AI 初筛（**个性化取读 + "与你何干"一句话 + 建议动作 + 建议入库线**）→ 每日简报（按线分组、三档上限、附选题推荐）→ 随手丢一键入库（决策树预归档，人抽查）。失败降级为"简报缺块"，不是系统故障。

**C. 知识层编译器**：三箱管道（收集/整理/沉淀）+ 编译管线（摄入→查询回填→lint 体检）+ 统一规则文档（库规：命名/字段/链接/输出格式）+ AI 自举起草库规（人审后生效）。

**D. 领域工作台**：
- 考公台：周计划（画像路由+确认）、错题归因（**引用依据**）、一键编译知识点卡、时政个性化筛选、薄弱点体检。
- 创作台：从库长出选题、剧本/分镜/提示词、角色卡/设定集、skills 技能库、成片复盘→提示词复用。
- MES 台：一键编译故障卡 + 月末 AI 归纳案例。

**E. 前台单壳**（见第 6 章）+ **AI 自治任务看板**（AI 自己维护任务/进度/待办，会话产物自动转任务，人只验收）。

### 5.4 红线（明确不做）

1. **无人值守自动入库**：一切 AI 产物（编译/沉淀/记忆写入）先进"待确认"，只降载到"只审不确定处"。
2. **原始素材永不动**：删除/覆盖只限临时区且 TTL 可配；正式区任何改动走写前快照+审计。
3. **无向量库/图库起步**：编译为主、轻检索为辅；出现真实可量化瓶颈才评估（旧原则保留）。
4. **不做多 Agent 编排/企业级权限**：单人场景。
5. **不绑定单一生态**：Obsidian/飞书/具体插件名都是可替换实现，吸收机制不吸收实现。
6. **防虚荣指标**：不显示"笔记数量增长"，只显示复利指标。
7. **PARA 十目录一步到位**：三箱起步，成熟后再扩展分区。

### 5.5 删除 / 冻结清单

| 处置 | 项目 |
|------|------|
| 冻结（代码保留、入口移除） | `/design-lab` 全部页面与 CSS 体系；旧 `GraphPage`；命令面板；星空全屏动效；P2 快照准入状态机（简化为一次确认）；五层记忆的晋升/评测机制（文件载体升格为记忆层） |
| 移出路线图 | 多智能体协作编排、自进化闭环、向量库（原则不变：没有真实使用数据不引入） |
| 待评估 | AgentMemory、Handoff 产品（仅文件记忆出现真实瓶颈时，走"合同冻结→影子模式→双轨比较→有限启用"） |
| 保留但降频 | System Health / Diagnostics / Safe Maintenance |

### 5.6 数据与隐私

代码、运行数据、Vault 三者分离不变；情报采集产物存 System 运行区可重建；画像/记忆不进公开仓库、不进日志；公司敏感资料维持禁止外发规则；抓取合规（公开源、频率上限、响应大小上限）。

## 6. 前台重设计

### 6.1 信息架构

一级导航（单壳，8 项）：`今日 情报 考公 创作 MES 资料 知识库 系统`

- 复盘、明日计划并入"今日"；工作规则并入"系统与设置"；画像/偏好编辑入口在"系统"。
- 移除 `/design-lab`、旧 `/graph`（FormalGraphPage 为唯一实现）。
- **随手丢**：全局常驻投递入口（顶栏按钮 + 快捷键），链接/文本/一句话/灵感直接丢入，AI 自动分拣。

### 6.2 首页 = 三线今日


保留 Vite + React 单应用、现有 API 层与测试设施；CSS 收敛为单一 token 层；路由简化；移除合成演示数据路径。

## 8. 迁移与风险

### 8.1 迁移

- 现有 Vault 数据不动、不迁移格式；已有 Raw/Wiki 继续有效。
- 旧路线图归档 `docs/roadmap/v2-archived/`；`project-handoff.md` 保留为历史记录。
- 旧代码只冻结不删除；Git 历史不动。
- 记忆层全为 Markdown：迁移项目 = 拷目录，换工具 = 新 Agent 读六槽。

### 8.2 风险

| 风险 | 应对 |
|------|------|
| 公告/时政源失效 | 采集器合同统一、失败降级、单源失效不影响简报其他块 |
| 模型成本（每日初筛+编译） | 轻量 prompt + 上限条数；本地 Provider 扩展位保留 |
| AI 编译错误污染知识层 | 全部走待确认；原始素材永不动；lint 体检兜底 |
| 工程挤占学习时间 | 阶段真实用一周验收；3 周半打完主干后工程时间降到维护级 |
| 考公/时政时效 | TTL 三态（fresh/warning/expired）+ 提醒，不自动删除 |
| 记忆隐私 | 画像/记忆不进公开仓库、不进日志；外发遵守隐私分级 |
| 跨 Agent 并发写 | 单写者约定 + 审计；冲突悬置由用户裁决 |
