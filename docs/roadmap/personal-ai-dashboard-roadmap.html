仓库风险与本方案修正

审查发现原实现风险本方案的处理
数据污染清理除哈希匹配外还会泛化处理长数字，自动 apply 存在误改可能。默认 dry-run，只展示精确 Diff；清理需人工批准并保留写前快照。
回滚范围主要恢复 4 个 WorkBuddy 文件，无法完整撤销钩子、服务、软链接和共享目录改动。每次 Release 携带完整变更清单和对应逆操作；恢复演练覆盖全部写入。
文件监听备份检测变化后再备份，首次写入时可能只得到修改后的版本。Publisher 在修改前创建快照；监听器仅作为第二道保险。
版本与文档漂移README 写 8 个 Skill，架构和 CI 检查 9 个，存在多份清单漂移。Manifest 作为唯一数据源，文档、适配器和健康页均由它生成。
端到端测试覆盖现有测试偏向评分器、格式和安装路径，跨 Agent 并发、完整回滚与一致性覆盖不足。发布前加入并发写入、故障中断、跨 Agent 失效和灾难恢复测试。

选择组件查看接入合同

重叠关系与选择原则

组合是否建议原因
AgentMemory + Handoff 产品默认不建议都保存跨 Agent 上下文、记忆或图数据，容易形成双主存储和冲突召回。
OpenContext/OCP + AgentMemory可以，但后期再做OCP 负责统一协议，AgentMemory 只作为 MemoryProvider 后端；不能分别维护事实副本。
OpenContext/OCP + Handoff 产品通常二选一两者都覆盖共享上下文、持久状态和会话协调；除非只把 OCP 当兼容适配器。
SDK Handoff + 任一上下文后端建议SDK Handoff 只负责运行内转交控制；上下文后端负责跨会话持久化，职责不同。
Markdown HandoffPacket + 无额外产品第一阶段推荐先验证交接字段和流程，未来可无损迁移到 OCP、AgentMemory 或 Handoff 产品。
